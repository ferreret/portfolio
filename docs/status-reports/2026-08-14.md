### 2.6 Incidente de autodeploy — diagnóstico y resolución

**Síntoma**: los pushes posteriores al README (9eea030, 11:46 UTC) dejaron de desplegar. Evidencia: `Last-Modified` del sitio congelado en 11:17:56 UTC (build del push del `.gitignore`) mientras entraban 3 pushes más.

**Diagnóstico a distancia** (sin acceso al panel): el repo no tiene webhooks clásicos → integración por GitHub App → Dokploy matchea el payload contra el nombre de repo guardado; tras el rename, `ferreret/portfolio` ≠ `ferreret/portolio` almacenado y los eventos se descartaban. El deploy del README (pre-rename) probablemente quedó atrapado por la ventana temporal del rename.

**Resolución**: Nicolás re-seleccionó el repo en Dokploy → Application → Source (mismo gesto que necesitó el reactor-classifier por la mañana). Verificación con push-sonda (`48a51ee`): push a las 12:08:56 UTC, sitio sirviendo el build nuevo a las 12:09:07 — **11 segundos**. Bundle regenerado (`index-DLFrIFNx.js`), contenido, capturas y PDFs verificados en 200.

**Mejora colateral**: `.dockerignore` nuevo en la raíz — el contexto de build subía `node_modules`, `dist`, `docs` y tooling en cada build. Ahora solo va el código fuente (parte del build de 11 s se explica por esto).
